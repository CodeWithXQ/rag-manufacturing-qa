# 制造设备故障知识库问答 Agent（RAG）

> 面向制造设备故障场景的垂直领域 RAG 知识库问答系统。核心亮点是**自主实现的混合检索**（向量检索 + BM25 关键词检索 + RRF 融合 + rerank 精排），并用召回率对比实验证明其优于纯向量检索。

---

## 一、项目定位

- **场景**：制造设备故障知识库问答（覆盖注塑机、数控机床、空压机、电机、PLC、变频器、液压、气动、机器人、传感器等 20+ 类设备）
- **核心改进点**：混合检索（Hybrid Retrieval），自己实现，不依赖 LangChain 等重框架
- **回答带引用**：答案附上引用的原文片段与出处，可溯源

## 二、核心亮点

- **自主实现的混合检索**：向量检索（FAISS + bge）+ BM25 关键词检索（jieba 分词）+ RRF 融合 + bge-reranker 精排
- **对比实验证明有效**：在 100 题测试集上，混合检索的 **MRR 提升 28.5%**（0.2458→0.3158），**Recall@1 从 2% 提升到 13%**
- **完整 RAG 链路自己实现**：文档切分、embedding 建库、检索、生成、引用解析，每一步都能讲清原理
- **生产级工程细节**：统一 LLM 接入层（OpenAI 兼容，可换 DeepSeek/通义/智谱）、本地模型推理（不烧 API 钱）、异常处理

## 七、混合检索原理

**为什么纯向量检索不够？** 向量检索懂语义（"电池鼓包"能联想到"膨胀"），但会漏掉文档里恰好有精确词的段落；BM25 精确命中关键词，但不懂同义词。两者互补。

**混合检索流程**：

| 步骤 | 做什么 | 说明 |
|---|---|---|
| ① 向量检索 | bge 把问题变成向量，FAISS 找最相似 top-20 | 找"意思相近"的 |
| ② 关键词检索 | BM25 按关键词匹配 top-20 | 找"有精确关键词"的 |
| ③ RRF 融合 | 对两路结果做 Reciprocal Rank Fusion（按排名倒数加权）去重 | 合并排序 |
| ④ rerank 精排 | bge-reranker 对融合结果重排，取最终 top-5 | 精挑一遍 |
| ⑤ 生成 | top-5 拼进 prompt 给 LLM，答案带引用编号 | 照着资料答 |

## 八、对比实验（真实数据，可复现）

```bash
python evaluate.py    # 纯向量 vs 混合 两列对比
python ablation.py    # 三组消融：纯向量 / 纯 BM25 / 混合
```

评估口径：**chunk 级**（比文档级更严格），检索前 k 个文本块中，命中"标准答案所在章节"（排查步骤/常见原因）才算召回成功。测试集 100 题。

**消融实验（三组对比，回答"各部分贡献多少"）**：

| 指标 | 纯向量 | 纯 BM25 | 混合检索 |
|---|---|---|---|
| Recall@1 | 2.00% | 2.00% | **13.00%** |
| Recall@3 | 42.00% | 20.00% | **46.00%** |
| Recall@5 | **61.00%** | 35.00% | 68.00% |
| **MRR** | 0.2458 | 0.1300 | **0.3158** |

**结论解读（消融贡献拆解）**：

- **向量检索 = 召回强、排序弱**：Recall@5 高达 61%（能召回），但 Recall@1 为 2%（top1 总是"标题/现象"块，而非真正的"排查/原因"段落）。它懂语义，但不够精确。
- **BM25 = 召回弱、排序也弱**：Recall@5 只有 35%（纯词面匹配，漏掉同义词/语义相近的段落），MRR 仅 0.1300（分数只看词频，排序不准）。它的价值在于"精确词面命中"，是向量检索没有的补充信号。
- **混合检索 = 取长补短**：向量负责"召回全"，BM25 补"精确命中"，RRF + rerank 负责"排序准"。结果 Recall@1 从 2%→13%（+11%）、MRR 从 0.2458→0.3158（+28.5%）。
- **诚实边界**：知识库扩到 100 篇后纯向量 Recall@5 掉到 61%（相似故障互相干扰），混合检索靠 BM25 兜底到 68%，说明两路互补缺一不可。

### Bad case 分析（32 题未命中，根因高度一致）

```bash
python bad_cases.py
```

根因：**「问题复述的是现象，答案在"排查步骤/常见原因"块，两者语义鸿沟大」**。检索把标准答案文档的「故障现象」块排到 top1（问题就是在描述现象，字面重叠），但真正的答案块因用词差异大被挤出 top5。

- **Case A（现象块霸榜 + 词面错位）**："空压机排气温度过高是什么原因？" → `05` 的「故障现象」排 top1，「常见原因」块缺席；反而液压泵/液压系统的「常见原因」块被 BM25 词面匹配拉进来。
- **Case B（文档对了、段落错位）**："液压系统油温过高怎么办？" → `14` 的 3 个块进 top5（现象/维修/预防），唯独「排查步骤」块没进。

**改进方向**：① 查询改写（"XX 怎么办"→"XX 的排查步骤"）；② 段落角色识别（rerank 前对"现象/原因/排查/维修"分类，优先原因/排查块）；③ 文档级召回 + 段落级重排两级结构。

## 九、生成评测（诚实边界）

评测集只有 gold_doc（标准答案文档）没有标准答案文本，无法自动判"答案对不对"，所以本项目只做检索指标（Recall/MRR），不做端到端生成答案评测。引用解析做了（prompt 要求 [1][2] 引用编号 + 正则提取 + 映射来源），但"引用命中率"没有独立评测脚本，不作为正式指标。
